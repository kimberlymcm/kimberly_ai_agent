# kimberly_ai_agent

A public agent for Kimberly McManus, running on Cloudflare Workers at `https://missiondistrict.ai/kimberly`. Other AI agents (and people) can talk to it three ways:

| Interface | URL |
|---|---|
| MCP (stateless streamable HTTP) | `/kimberly/mcp` |
| A2A (JSON-RPC `message/send`) | `/kimberly/a2a`, card at `/kimberly/.well-known/agent.json` |
| Plain text profile | `/kimberly/llms.txt` (also `/kimberly` for non-HTML clients) |

## Tools

- `ask_kimberly`: answers questions from `src/profile.ts` and her Substack posts, using Claude.
- `request_meeting`: queues a meeting request for her review. Nothing is booked.
- `leave_message`: queues a message.

Over A2A, plain text is a question; prefix with `/meeting ` or `/message ` to use the other two.

## How it works

- `src/profile.ts` is the single source of truth for who she is and what the agent must not share.
- `src/posts.generated.json` holds her Substack posts, generated by `npm run sync` from the RSS feed. Posts listed in `LINK_ONLY` in `scripts/sync-substack.mjs` keep their title and link but their text is excluded.
- Messages and meeting requests go to a KV namespace (`INBOX`, 90-day expiry) and trigger an email via Resend. Questions trigger a digest email at most once an hour.
- `GET /kimberly/admin/inbox` returns queued items; it needs `Authorization: Bearer <ADMIN_TOKEN>`.

## Setup

```
npm install
npx wrangler login
npx wrangler kv namespace create INBOX     # put the id in wrangler.toml
```

Set secrets (pipe the value in so it never appears in a command; `wrangler secret put` has no prompt in non-interactive shells):

```
pbpaste | npx wrangler secret put ANTHROPIC_API_KEY
pbpaste | npx wrangler secret put ADMIN_TOKEN        # e.g. from `openssl rand -hex 32`
pbpaste | npx wrangler secret put RESEND_API_KEY
pbpaste | npx wrangler secret put ALERT_TO           # where alerts are sent
```

Resend needs `missiondistrict.ai` verified as a sending domain (alerts come from `agent@missiondistrict.ai`; override with an `ALERT_FROM` var). `missiondistrict.ai` must be a zone on the Cloudflare account for the route in `wrangler.toml` to attach.

## Everyday tasks

```
npm run dev          # local, http://localhost:8787/kimberly
npm run typecheck
npm run sync         # refresh Substack posts (feed exposes the latest 10)
npx wrangler deploy
curl -H "authorization: Bearer $ADMIN_TOKEN" https://missiondistrict.ai/kimberly/admin/inbox
```

## Notes

- Rate limiting is a best-effort in-memory per-IP cap (30 POSTs/min). Add a Cloudflare rate limiting rule for real enforcement, and set a spend limit on the Anthropic key.
- The agent treats incoming questions as untrusted input, but the profile and posts are the only things it should ever reveal. Keep private details out of both.
